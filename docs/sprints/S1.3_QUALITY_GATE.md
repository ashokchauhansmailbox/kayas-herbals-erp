## 3. Issues found & fixed during this pass

### 3.1 🔴 HIGH — Supervisor was running the legacy Mongo MVP (`server.py`), not the new FastAPI app

- **Discovery:** `/var/log/supervisor/backend.err.log` showed a crash loop: `KeyError: 'JWT_SECRET'` from `backend/server.py:23`. Container reported `RUNNING` because uvicorn `--reload` kept respawning.
- **Impact:** The new v1 API (`app.main:app`) was never actually reachable through supervisor — only via ad-hoc `pytest` runs. Anyone hitting `http://localhost:8001/api/v1/...` in the preview would have gotten timeouts. Legacy code path leaked into runtime.
- **Fix:** `/etc/supervisor/conf.d/supervisord.conf` — repointed `[program:backend]` from `uvicorn server:app` → `uvicorn app.main:app`. `supervisorctl reread && update` cycled the process cleanly.
- **Verification:** `GET /api/v1/health/{live,ready,db}` → 200 · e2e JWT flow → 200.

### 3.2 🟠 MEDIUM — N+1 query on role permission assignment (RBAC hot path)

- **Discovery:** `POST /api/v1/roles` and `PATCH /api/v1/roles/{code}` looped per permission code:
  ```python
  for pcode in payload.permissions:
      perm = (await db.execute(select(Permission).where(Permission.code == pcode))).scalar_one_or_none()
  ```
  A `super_admin` role has 89 permissions → **89 round-trips** to Postgres per role create/update.
- **Fix:** batched into a single `Permission.code.in_(payload.permissions)` fetch + dict lookup in `app/api/v1/routes/admin.py` (both `create_role` and `update_role`). Missing permissions are still reported with the first unknown code.
- **Verification:** 119/119 pytest still green; ruff + mypy clean.

### 3.3 🟡 LOW — OpenAPI/Postman baseline drift

- **Discovery:** `check_openapi_drift.py` reported that the pagination bounds added on `page` / `page_size` (`minimum: 1`, `maximum: 200`) were not reflected in `docs/api/openapi.{json,yaml}`. Postman was in sync.
- **Fix:** regenerated `openapi.{json,yaml}` and `postman_collection.json` via `scripts/generate_openapi.py` + `scripts/generate_postman.py`. Baseline is now clean.
- **Guardrail:** CI job `openapi-drift` blocks any future drift.

### 3.4 🟡 LOW — Import ordering (isort) not enforced

- **Discovery:** Enabling ruff `I` rule surfaced 30 files with non-canonical import order (30 auto-fixable).
- **Fix:**
  - `ruff check --select=I001 --fix backend/app backend/tests backend/migrations scripts` — 30 files re-ordered.
  - **New file** `backend/pyproject.toml` pins the enforced rule set (`E, F, W, I, B` + `known-first-party = ["app", "migrations"]`) so drift is now caught by the existing `ruff check` CI step. No CI YAML change needed.
- **Verification:** ruff + mypy + pytest all green.

### 3.5 🟠 MEDIUM — `/auth/me` auto-provision raised 500 on email collision

- **Discovery:** surfaced by the testing agent on the first regression pass (`iteration_1.json`). When a JWT was minted with a **new** `sub` UUID but an **email that already existed** in `users`, the auto-provision INSERT hit `uq_users_email` and bubbled up as `IntegrityError` → 500. Reproducible with two `mint_token(email="qa@example.com")` calls having distinct `sub`s.
- **Fix:** `app/services/auth_service.py::load_current_principal` now pre-checks `users.email` before insert and raises `AuthError("auth.email_conflict")` → 401 with unified error envelope, instead of a raw 500. Silently binding to the pre-existing row would be a security risk (identity swap), so the caller is told to reconcile.
- **Regression test:** `tests/test_auth.py::test_email_collision_on_autoprovision_returns_401` added — mints one user, then a fresh sub with the same email; asserts 401 + `auth.email_conflict`.
- **Verification:** 120/120 pytest green (was 119 before this test).---

## 4. Deep scans — findings

### 4.1 Dead code

- `vulture --min-confidence 80` found **1** unused variable → false positive: `app/services/audit_service.py:59` `tb` argument of `async def __aexit__(self, exc_type, exc, tb)`. It is required by the Python async-context-manager protocol; removing it would break the `async with AuditContext(...)` idiom. **No action.**

### 4.2 Duplicate code

Batch permission-lookup logic in `admin.py` is used twice (create_role, update_role) but each call site has a distinct audit envelope, so extracting into a helper today adds indirection without saving lines. **Deferred — will reassess when Sprint 1.4's `distributor.py` uses a similar pattern.**

### 4.3 Unused imports / dependencies

- Ruff `F401` (unused import) — 0.
- `requirements.txt` — all 19 packages transitively used by the app or its test tooling. `pipdeptree` cross-check: no orphaned direct deps.

### 4.4 Circular dependencies

- Import chain smoke test succeeded: `app.main → app.api.v1 → app.core.security → app.services.auth_service → app.services.audit_service → app.seeds.run` all import in a single Python session without side-effects. `deps.py → auth_service.py → deps.py` is a **layered downcall**, not a cycle: `deps.get_current_user` calls `AuthService`, but `AuthService` imports only `models`/`db`/`sqlalchemy`, not `deps`. ✅

### 4.5 Architectural violations

- No `sqlalchemy.orm.Session` (sync) usage anywhere in `app/*`.
- No route file imports another route file.
- Services (`services/*.py`) never import routes.
- Models never import services.
- Seeds never import routes or services.

- **One boundary softness:** `app/deps.py` mixes DB session provisioning with auth resolution. It's small (< 100 LOC) and idiomatic FastAPI, so we're keeping it. **No action.**

### 4.6 Security issues

- **Bandit:** 0 findings across 3 212 LOC.
- **pip-audit:** 0 known CVEs on the current lock (`fastapi 0.139.0`, `starlette 1.3.1`, `pyjwt[crypto] 2.13.0`, `sqlalchemy 2.0.36`, `alembic 1.14.0`, `deepdiff 8.6.2`).
- **JWT verification:** HS256 only; validates `iss`, `aud`, `exp`, `nbf`, `iat`; rejects `alg=none`.
- **Session revocation:** `sessions.jti` + `revoked_at`; `/auth/logout` sets `revoked_at = now()`.
- **RBAC:** every mutating route wears `Depends(require("<code>"))`; failed checks return 403 with unified `code/message/details` envelope.
- **OWASP suite:** `tests/test_audit_security.py` covers alg confusion, tampered signature, expired token, none-alg, missing sub, wrong aud, wrong iss, mixed super_admin/anonymous, request_id leak, XSS body reflection. All green.
- **Legacy Mongo MVP** (`backend/server.py`, 400+ LOC, still uses `bcrypt` + a hand-rolled JWT layer) is no longer wired to supervisor (fix 3.1). **Recommendation:** delete during Sprint 2 UI cutover, per PRD.

### 4.7 Performance bottlenecks

  - `GET /users` — 1 + 1 aggregate (users + `_batch_role_codes_for_users`).

## 6. Security Report

- **Authn:** Supabase JWT HS256 verify, `iss=SUPABASE_JWT_ISSUER`, `aud=SUPABASE_JWT_AUDIENCE`, clock-skew 5 s, `mint_token()` guarded behind `if os.getenv('APP_ENV') != 'production'`.
- **Authz:** Capability-based RBAC, 89 permissions × 9 system roles. `require("<code>")` decorator on every mutating route.
- **Session revocation:** `sessions.jti` + `revoked_at`; `POST /auth/logout` marks revoked.
- **Suspension / deletion:** `users.status ∈ {active, invited, suspended, deleted}`; `AuthService` short-circuits with 401/403.
- **Audit:** every state change wrapped in `AuditContext` — before / after JSONB + deepdiff, same transaction as the mutation. Read events go to `activity_logs`.
- **Static:** Bandit 0, pip-audit 0.
- **Transport:** CORS restricted via `settings.CORS_ORIGINS`; unified error envelope prevents stack-trace leaks in production.
- **OWASP top 10 coverage in tests:**
  - A01 broken access control → `test_rbac.py`
  - A02 crypto failures → `test_audit_security.py::test_algorithm_confusion_rejected`
  - A03 injection → SQLAlchemy 2 params only, no string SQL
  - A07 identification & authn failures → `test_auth.py` (expired, tampered, none-alg)
  - A09 logging & monitoring failures → audit + activity separation

**Outstanding security items for staging:**
- Rotate `SUPABASE_JWT_SECRET` in `backend/.env` before staging deploy (currently the dev placeholder).
- Add rate limiting on `/api/v1/auth/*` (Redis-token-bucket) in Sprint 1.5 alongside Payments.
- Wire Supabase RLS policies for defence-in-depth (Sprint 1.6, per `docs/architecture/04-rls-policies.md`).
