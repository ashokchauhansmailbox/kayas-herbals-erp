## 3. Fixes and refactors this sprint

### 3.1 🟡 Bug — `test_migrations_cycle::clean_test_db` didn't re-seed after teardown

- **Discovery:** the moment Sprint 1.4 added enough test files for the loadscope scheduler to land `test_migrations_cycle` and the new master-CRUD suites on the same xdist worker, the CRUD suites began failing with `sqlalchemy.exc.NoResultFound` — the migration-cycle fixture had left the DB at `head` but never re-seeded the 89 permissions and 9 roles that the RBAC-guarded mint fixture depends on.
- **Fix:** teardown of `clean_test_db` now runs `python -m app.seeds.run` after `upgrade head`. Idempotent seed keeps this cheap.
- **Verification:** 164/164 pytest green in ~12 s.

### 3.2 🟡 Robustness — validation errors from `field_validator` returning raw `ValueError`

- **Discovery:** endpoint `POST /api/v1/vendors` with a code containing whitespace raised a `TypeError: Object of type ValueError is not JSON serializable` because Pydantic v2 `field_validator` puts the raw `ValueError` in `ctx` and the FastAPI validation handler passes `exc.errors()` straight to `JSONResponse`.
- **Fix:** `validation_handler` now runs the error list through `fastapi.encoders.jsonable_encoder` so any nested exception object collapses to a string. Preserves the payload shape.
- **Verification:** covered by `test_purchase.py::test_vendor_rejects_invalid_code` (422 with `validation_error`).

### 3.3 🟢 Refactor — models registry expansion

- `app/models/__init__.py` re-exports every new class so Alembic autogenerate keeps a full picture. Test `test_no_autogenerate_drift` remains green.
- Address model gained a proper `postgresql_where` partial-unique `Index` (previously implicit via raw `op.execute`); Alembic now sees the same object migration 007 built.
