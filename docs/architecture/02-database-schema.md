# 02 — Complete PostgreSQL Schema

_Every table, every column, every index, every constraint. DDL is illustrative — final SQL is generated by Alembic in Sprint 1._

## Global conventions
- PKs: `id UUID DEFAULT gen_random_uuid()`
- Timestamps: `created_at TIMESTAMPTZ DEFAULT now()`, `updated_at TIMESTAMPTZ`
- Actor tracking: `created_by UUID REFERENCES users(id)`, `updated_by UUID REFERENCES users(id)`
- Soft delete: `deleted_at TIMESTAMPTZ NULL`, `deleted_by UUID NULL`
- Concurrency: `version INT DEFAULT 1` (optimistic lock, bumped by trigger)
- Money: `NUMERIC(14,2)`, Percentages: `NUMERIC(5,2)`
- Enums declared as native Postgres `CREATE TYPE`

## Enums
```sql
CREATE TYPE user_status AS ENUM ('invited','active','suspended','deleted');
CREATE TYPE stock_state AS ENUM ('available','reserved','damaged','returned','expired');
CREATE TYPE stock_move_type AS ENUM ('inward','outward','transfer_in','transfer_out','adjust_plus','adjust_minus','damage','return','expire','reserve','release');
CREATE TYPE order_status AS ENUM ('draft','confirmed','packed','shipped','delivered','cancelled','returned');
CREATE TYPE order_source AS ENUM ('web','distributor','pos','admin_manual');
CREATE TYPE payment_status AS ENUM ('pending','authorized','captured','failed','refunded','partially_refunded');
CREATE TYPE invoice_status AS ENUM ('draft','issued','void','paid','partially_paid');
CREATE TYPE gst_mode AS ENUM ('intra','inter','exempt','zero');
CREATE TYPE kyc_status AS ENUM ('pending','submitted','verified','rejected');
```

## Common indexing rules
- Every FK → B-tree index.
- Every `status`/`state` enum → filtered partial index where value ≠ terminal.
- Every `*_at` used in reports → composite index with tenant/status.
- Full-text: `products.tsv` (GIN), `customer_profiles.search_tsv` (GIN).
- Audit/activity tables partitioned by month (declarative, added at S12 hardening).

## Referential integrity
- No hard deletes on financial docs (`invoices`, `credit_notes`, `debit_notes`, `payments`, `refunds`) — enforced by trigger `raise on DELETE`.
- Order → invoice → payment chain uses `SERIALIZABLE` transactions on writes.
